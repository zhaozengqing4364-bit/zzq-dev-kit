# ZZQ 项目接入

用户要求安装、接入、检查或升级开发体系时使用。接入目标是让后续Agent找到真实规则与任务，不代表应用已验收。

1. 先确认当前项目路径、Git状态和已有AGENTS/CLAUDE规则，读取目标目录的局部约定。只读请求仅调查；明确要求接入可执行必要的可逆配置。
2. 用`npx zzq-dev-kit@1.0.0 init --dry-run --json`检查当前环境与改动；命令不存在时先检查Node/npm或用户提供的实际安装源。已安装且只检查时用`doctor --json`。遵循项目已选user/project范围与Agent集合，不重复安装同名技能。
3. 有不同内容的旧技能、链接、修改过的接入块或配置错误时，列出具体对象、差异、保留/备份迁移选项及推荐。用户未决定前保留原件，不用删除、--force、改名隐藏或修改记录绕过冲突。已明确授权的同一选择不重复问。
4. 完整预览无冲突后，在已有接入授权内运行init。新项目由官方引擎建立最小OpenSpec；已有项目保留配置与Schema。CLI只安装工具并添加接入指针，不执行目标项目的应用脚本，也不把空文档伪装成业务基线。
5. 调查真实项目入口、模块边界、领域术语和现有package/构建/测试脚本；区分已观察行为、约定行为与未知。新项目未确定的技术选择不编造。老项目先聚焦下一项真实工作，不要求全仓回填规格。
6. 将有依据的项目事实放回已有AGENTS、OpenSpec context或项目导航的合适位置，只补缺口，不整份替换；没有必要就不新建词汇表、ADR或第二套任务表。未知的重要业务/权限取舍给推荐选项。凭据、个人资料和环境秘密留在当地，不复制到共享配置或报告。
7. 运行doctor并核对实际Schema/产物与规则是否可发现。已有有效验证复用，安装本身不授权UI/外部模型/供应商/生产操作；项目采用什么测试政策就遵守什么。
8. 交付安装版本、真实改动、检查结果、未决项和下一步：目标模糊交grill-with-docs，事实待查交explore，明确原型交prototype，方向明确交design，已有方案交apply。原10技能继续同一change；项目未要求OpenSpec时只给建议，不擅自初始化。

升级用`upgrade --dry-run`比较已管理文件，升级失败或中断先doctor定位事务，再按明确对象用`rollback <ID>`。恢复拒绝后续编辑时先讨论合并，绝不以恢复名义覆盖用户新工作。
