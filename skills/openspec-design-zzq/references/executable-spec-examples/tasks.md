# 可执行规格任务示例

仅在已明确采用spec-as-source时参考，保留当前Schema的任务结构；删掉不适用项。已有runner直接复用，新验收栈或报告设施只在明确需要时建设。

## 1. 本次完整业务结果

- 依据：现行需求/场景与原失败。
- 位置/依赖：实际规格、实现和已有runner入口。
- [ ] 1.1 写明可观察业务场景，并证明现有行为在原问题处失败或确有实现缺口。
- [ ] 1.2 完成最小实现及直接消费者、反馈/恢复，使用本次最低有效检查验证。
- [ ] 1.3 核对有效规格组合与原失败复验，记录版本、环境、实际证据和未执行边界。

提取/组合器本身变化时补其契约回归；普通功能不自动运行全部工具栈。Git提交、stash、主线检查点和受限运行按当前授权，不嵌入每个步骤。
